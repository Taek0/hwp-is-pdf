# Rust HWP/HWPX → PDF 엔진 개발

본 제품은 한컴의 HWP 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다.

현재 구현된 입력 경로는 **HWP 5 바이너리와 HWPX**입니다. CFB/DEFLATE 레코드 및 ZIP/XML 파싱, 저장된 줄 배치 해석,
글자·수식·표·그림 배치, 글꼴 포함 PDF 생성까지 Rust 라이브러리 안에서 수행합니다.
한컴 뷰어, 한컴 DLL, 프린터, Python 프로세스를 실행하지 않습니다.

기존 Python 프로토타입과 전용 의존성·빌드 산출물은 정리했습니다.
`../engine/`에는 초기 조사 자료와 비교용 출력만 남아 있습니다.
두 기존 HWP 파일도 Rust 엔진에서 직접 변환합니다. 제공된 세 문서의 검증을 통과했으며,
모든 HWP 문서에 대한 완전한 호환성을 의미하지는 않습니다.

현재 지원 범위·남은 기능·우선순위는 [FORMAT_COVERAGE.md](FORMAT_COVERAGE.md)의
2026-10-15 현황을 기준으로 확인합니다. 최신 개선은 한글 기울임, 위·아래첨자,
부호 있는 글자 위치 및 장식 위치 반영입니다. 기울임 각도·첨자 크기는 명시적 근사입니다.
기존 43개 문서 210쪽을 재변환했고 184쪽은 픽셀 동일, 26쪽은 원본 서식 반영으로
변경됐습니다. 원본·추출 텍스트·페이지/개체 수 유지, 45개 테스트 통과.
결과와 QA는 `output/scripts-regression/SUMMARY.html`에 있습니다.

긴 텍스트 각주의 연속 페이지 처리와 페이지보다 큰 중첩 개체의 비율 축소를
추가했습니다. 각주 연속 페이지를 먼저 출력한 뒤 본문을 재개하며, 큰 중첩 표의
일반적인 구조 분할은 아직 제한됩니다. 최신 검증: `output/overflow-regression/SUMMARY.html`.

이후 중첩 표의 원래 크기 분할, 반복 머리행·상하 캡션, 그림·회전 개체·각주가
섞인 경우의 페이지 배치를 추가했습니다. 최신 결과는
`output/mixed-tables/SUMMARY.html`이며 자세한 지원 조건은 `FORMAT_COVERAGE.md`에 있습니다.

일반 문단과 표·그림·회전 사각형·각주가 섞인 구역의 줄바꿈과 페이지 나누기를
계산합니다. 최상위 문단의 줄 배치가 없으면 자동으로 재배치하며, 기존 캐시는
기본 변환에서 유지합니다. `--reflow`로 강제 재계산하며 `--reflow-text`도
같은 동작을 합니다. 셀의 실제 폭에서 줄을 다시 나누고 각주 공간을 확보하며,
표가 끝난 페이지에서 본문을 이어갑니다. 셀 높이는 원래 값을 최솟값으로 유지합니다.

지원 조건 밖의 떠 있는 개체는 문서 순서의 블록으로 배치합니다. 복잡한 감싸기,
수식·미주·RTL·구역 내 단 변경의 강제
재배치는 아직 지원하지 않습니다. 세부 조건은 `FORMAT_COVERAGE.md`를 확인하세요.
최신 검증: `output/reflow-mixed/SUMMARY.html` (67개 테스트, 기존 43개 문서
210쪽 픽셀 동일). 혼합 예제의 캐시 유무에 따른 재배치 PDF도 동일합니다.

번호·글머리표 문단도 재배치합니다. 번호 폭·글꼴·본문 간격을 줄바꿈에 반영하고,
문단의 여백·내어쓰기에서 본문 시작 위치를 계산합니다. 계층 번호의 이어짐과
상위 번호 변경 시 하위 번호 초기화, 페이지를 넘는 항목의 번호 중복 방지를
검증했습니다. 현재 숫자 템플릿과 문자 글머리표 중심이며, 그림 글머리표 및
블록 개체로 시작하는 목록 항목은 강제 재배치에서 명시적으로 거부합니다.
최신 결과: `output/reflow-lists/SUMMARY.html`. 번호 예제 5쪽과 공개 HWP 각주
예제 8쪽을 검증했습니다. 전체 71개 테스트와 Clippy가 통과했으며 기존 43개 문서
210쪽은 픽셀 동일합니다. 한컴 원본과 동일한 페이지 나눔을 보장하지 않습니다.

같은 폭의 2단·3단 흐름에서 표·그림·회전 개체·각주를 재배치합니다. 표 조각과
반복 머리행을 다음 단으로 이동하고, 마지막 단이 끝나면 다음 페이지로 이어갑니다.
각주는 기준 행의 단에 배치하며 표 뒤 본문은 마지막 조각 아래에서 재개합니다.
단을 합친 각주나 오른쪽 끝 단 각주는 이 혼합 재배치 경로에서 아직 지원하지
않습니다. 서로 다른 단 너비, 단 높이 균등 맞춤 및 구역 중간 단 변경도 남아 있습니다.
최신 검증: `output/reflow-columns/SUMMARY.html` (72개 테스트·Clippy 통과,
기존 43개 문서 210쪽 픽셀 동일).

문단 맨 앞의 왼쪽·오른쪽 그림과 사각형 도형은 사각 영역을 피해 글을 감쌉니다.
개체 아래에서 원래 줄 폭으로 복구하고, 짧은 문단 뒤의 일반 문단도 감싸기를 이어갑니다.
개체와 옆 본문은 같은 단·페이지에 두며, 각주 공간도 반영합니다. 옆 공간이 부족한
그림은 본문을 아래로 보내는 기존 블록 배치로 처리합니다.
일반 위치 및 윤곽선 옵션의 최신 지원 조건은 아래 설명을 확인하세요.
최신 검증: `output/reflow-floats/SUMMARY.html` (75개 테스트·Clippy 통과,
기존 43개 문서 210쪽 픽셀 동일).

그림의 남은 영역을 후속 일반 문단에 전달해 여러 문단에 걸친 감싸기를 지원합니다.
각 문단의 여백·간격을 반영하고, 그림 옆 영역에 해당하는 문단과 각주를 함께 배치합니다.
새 개체·번호 문단·문단 보호 설정·강제 쪽 나눔을 만나면 이전 그림 아래로 내려갑니다.
구역 끝에서도 남은 그림 높이를 확보합니다. 최신 검증은
`output/reflow-float-flow/SUMMARY.html`에 있습니다. 78개 테스트와 Clippy가 통과했고,
기존 43개 문서 210쪽은 이전 이미지와 동일합니다.

같은 문단 앞의 왼쪽·오른쪽 개체 두 개를 동시에 감쌉니다. 각 개체의 높이를
따로 추적해 짧은 개체 아래에서는 한쪽 폭을 먼저 되찾고, 긴 개체 아래에서는
전체 폭으로 복구합니다. 후속 문단에도 두 영역을 전달합니다. 가운데 공간이
부족하면 블록으로 배치하고, 후속 문단의 여백이 크면 개체 아래로 이동합니다.
이후 일반 위치 배치로 같은 쪽과 후속 문단의 개체 처리도 확장했습니다.
최신 검증: `output/reflow-paired-floats/SUMMARY.html` (82개 테스트·Clippy 통과,
기존 43개 문서 210쪽과 이전 감싸기 예제 5쪽 픽셀 동일).

문단·단 내부에서 가로·세로 오프셋, 중앙 정렬, 같은 쪽의 여러 개체와 후속 문단의
새 개체를 배치합니다. 한 문단 최대 32개를 처리하며 겹침 금지 개체는 충돌 시 아래로
이동하고 경고를 기록합니다. `LEFT_ONLY`·`RIGHT_ONLY`도 반영합니다.
`--contour-wrap` 옵션은 재배치를 켜고 타원·다각형·회전 사각형의 기하 윤곽을
따라 본문을 배치합니다. 기본 `--reflow`는 원본의 사각 감싸기를 유지합니다.
BOTH_SIDES는 같은 줄의 여러 구간을 사용하고, LARGEST_ONLY는 가장 넓은 구간을 선택합니다.
투명 그림은 PDF 마스크로 보존하며 자르기·회전을 반영한 불투명 영역을 사용합니다.
음수·절대 위치와 큰 개체는 아래 2단계 규칙으로 처리합니다.
복잡한 그룹 변환과 셀 내부 감싸기는 남아 있습니다.
최신 결과: `output/reflow-contours/SUMMARY.html` (91개 테스트·Clippy 통과,
기존 43개 문서 210쪽과 이전 감싸기 예제 5쪽 픽셀 동일).

현재 10단계 개선을 순서대로 진행 중이며 `roadmap-progress.json`에 상태를 기록합니다.
1단계는 투명 그림, 닫힌 베지어 곡선, 그룹 내부 빈 공간, 다각형의 내부 구멍,
같은 줄의 여러 구간을 구현했습니다. 96개 테스트와 Clippy가 통과했습니다.
기존 210쪽 중 209쪽은 동일하며 1쪽은 투명 로고의 검은 배경을 수정한 결과입니다.
이미지·검증 보고서: `output/roadmap/01-wrapping/SUMMARY.html`.
한컴 출력과의 비교는 요청대로 10단계 완료 후에 진행합니다.

2단계는 음수 오프셋의 선행 여백, PAGE/PAPER 절대 좌표, 큰 그림·그룹의 비율 맞춤,
연결 개체의 분리를 구현했습니다. 절대 앵커 문단은 새 재배치 페이지에서 시작하고,
다단에서는 해당 개체 아래를 이후 단의 시작 위치로 삼는 보수적인 배치를 사용합니다.
한 문단의 연결 개체가 너무 크면 문서 순서의 블록으로 배치하며 경고를 남깁니다.
100개 테스트·Clippy 통과, 기존 43개 문서 210쪽 동일.
결과: `output/roadmap/02-anchors/SUMMARY.html`.

## 실행

Rust stable / edition 2024 환경에서:

```sh
cargo run -- input.hwpx output.pdf /path/to/fonts
cargo run -- input.hwp output.pdf /path/to/fonts
cargo run -- input.hwpx output.pdf /path/to/fonts --reflow
cargo run -- input.hwpx output.pdf /path/to/fonts --contour-wrap
cargo test
cargo clippy --all-targets -- -D warnings
```

글꼴 디렉터리는 다음 TrueType 파일을 제공해야 합니다.
`malgun.ttf`, `malgunbd.ttf`, `arial.ttf`, `arialbd.ttf`, `times.ttf`,
`timesbd.ttf`, `seguisym.ttf`. HWP 명조체에는 `batang.ttc`를 사용하고,
한자·기호에는 설치된 `simsun.ttc`, `msgothic.ttc` 등을 보충 글꼴로 사용할 수 있습니다.
TTC는 Rust에서 단일 TrueType 글꼴로 추출한 뒤 PDF에 포함합니다.
Windows에서는 기본값 `C:/Windows/Fonts`, 현재 WSL 검증 환경에서는
`/mnt/c/Windows/Fonts`를 사용합니다. 글꼴은 저장소에 복사하거나 재배포하지 않습니다.
한컴 전용 글꼴은 OS 글꼴로 대체하고 변환 보고서에 기록합니다.

라이브러리 API:

```rust
hwp_engine::convert(input_path, output_path, font_directory)?;
// 지원되는 혼합 구역의 저장된 줄 배치를 무시하고 다시 계산:
hwp_engine::convert_with_reflow(input_path, output_path, font_directory, true)?;
// 기하 윤곽선 감싸기를 명시적으로 선택:
hwp_engine::convert_with_options(input_path, output_path, font_directory, true, true)?;
```

`run-cargo.sh`는 이 작업 공간의 격리된 WSL Rust 도구 체인을 사용하는 편의 스크립트입니다.
일반 개발 환경에서는 표준 `cargo` 명령을 사용하면 됩니다. EXE 배포 패키지는 만들지 않습니다.

## 구조

- `src/model.rs`: 크기 제한을 적용한 HWPX ZIP/XML 로딩, 문자·문단·테두리 정의와 이미지 참조.
- `src/hwp.rs`: 읽기 전용 CFB 저장소, HWP 압축 스트림/CRC, 길이·중첩 제한이 있는 레코드 파서,
  문단/글꼴/표/바탕쪽/그림 정규화, PCX 해독, 한컴 전용 표시 문자 처리.
- `src/layout.rs`: 공개 Engine API, 상태 및 변환 흐름 조정.
- `src/layout/text_style.rs`, `text_paint.rs`: 글자 측정·서식과 텍스트 출력.
- `src/layout/object_paint.rs`: 개체 출력, `table_layout.rs`·`table_pagination.rs`: 표 배치·분할.
- `src/layout/notes.rs`, `page_decorations.rs`: 각주·미주와 머리말·꼬리말.
- `src/layout/reflow*.rs`: 페이지·단 흐름, 문단, 표 셀, 개체 감싸기 준비를 역할별 분리.
- `src/reflow.rs`, `wrap_region.rs`, `image_layout.rs`: 줄 구간 선택, 윤곽선 교차, 이미지 불투명 영역.
- `src/math.rs`: 제공된 시험지의 숫자, 변수, π, 각도, 괄호, 위첨자, 분수, 단위, 선분 표시.
- `src/pdf.rs`: PDF 객체/스트림, TrueType 글꼴 포함, CID/ToUnicode, 벡터 글자/선과 이미지 출력.
- `src/lib.rs`: 변환 API. `src/main.rs`: 개발·검증용 CLI.
- `src/qa.rs`: PDF와 같은 벡터 연산에 대한 글리프 경계·다른 글자/도형 선/그림 영역 충돌 검사.
- `tests/hwp_regression.rs`: 두 HWP의 직접 변환, 원본 보존, 페이지 수와 객체 수, 충돌 회귀 검사.
- `tests/hwpx_regression.rs`: 사용자 제공 문서 회귀 테스트. 원본 문서는 소스에 포함하지 않음.

## 제공된 HWPX 검증

입력: `../2단_수학시험지_변환검증_7826.hwpx`.
출력: `output/math-exam.pdf`, `output/math-exam.report.json`.

- 9쪽 출력. 입력의 빈 문단으로 이루어진 쪽도 유지.
- 수식 249개와 그림 22개를 렌더링 경로에서 확인.
- 중첩 표, 반복되는 꼬리말 표, 미주 26개 포함.
- 기존 HWPX 실제 문서 통합 테스트 유지.
- 전 페이지 PNG 및 모아보기로 시각 검사.
- PDF 단어 중심이 이미지 사각형 내부에 들어가는 사례 0건.
- 페이지 영역 밖의 PDF 단어 0건.

마지막 두 검사는 보조 지표이며, 글자 간 모든 겹침이나 원본과의 픽셀 일치를 증명하지 않습니다.
`output/visual-qa.json`에는 검사 범위와 PDF 해시가 기록되어 있습니다.

도형 테두리 교차, 전경 그림 영역 침범이 모두 0건이어야 통과합니다.
복학원서에서 파일 자체가 글 뒤 배치로 지정한 그림 2개는 의도된 배경으로 별도 집계합니다.
배경 로고는 회색조·밝기·대비 효과를 적용합니다. 효과의 픽셀 값은 한컴과 완전히 동일하다고 보장하지 않습니다.

검사 결과는 각 PDF 옆의 `*.qa.json`에 기록됩니다. 검사는 실제 TrueType 글리프의
경계 상자와 가로/세로 선을 사용합니다. 같은 줄에서는 자연스러운 작은 커닝은 허용하고
글리프 폭의 45% 이상 겹치는 경우를 탐지합니다. 모든 픽셀·곡선 교차를 증명하는 검사는 아닙니다.
문서의 PNG 모아보기와 개별 페이지 시각 검사를 함께 수행했습니다.

이번 HWP 지원 과정에서는 첫 쪽 바탕쪽 숨김, 아래쪽 기준 개체 오프셋 방향,
중첩 셀에서의 사용 가능 폭, 좁은 글상자의 음수 자간으로 인한 겹침을 수정했습니다.
원본 HWP/HWPX 회귀 검사에 더해 공개 기능 문서, 차트 값 보존, 수식 중첩 한계,
공고문/FAQ 자간 충돌 검사를 `tests/feature_regression.rs`에 추가했습니다.

## 이번에 수정한 겹침 원인

1. **부호 있는 오프셋**: `4294966449`는 실제로 `-847 HWPUNIT`입니다.
2. **중첩 표 좌표계**: 페이지/단 좌표와 셀 내부 좌표를 구분합니다. 내부 부동 표의
   음수 시작점과 실제 바닥점을 셀 높이에 포함합니다. 최소 표 높이도 보존합니다.
3. **수식·그림의 자리**: 글자와 같은 줄 안에서 객체 폭과 바깥 여백을 소비합니다.
   수식은 원본 지정 폭·높이·기준선을 가진 별도 배치 상자로 처리합니다.
4. **오래된 글상자 배치 높이**: 21번 문제의 객체 `1653018157`은 `sz.height=3819`이지만
   `curSz.height=6866`, 내부 텍스트 높이 6300 + 상하 여백 566입니다.
   실제 높이 68.66pt를 사용하고, 이후 본문을 차이 30.47pt만큼 이동시킵니다.
   내부 네 줄이 프레임에 포함되는지와 다음 선택지가 프레임 아래에 있는지 테스트합니다.

## 검증 범위와 남은 작업

- 원본 전용 글꼴의 외형·메트릭을 완전히 재현하지 않습니다.
- 기본 변환은 저장된 줄 배치를 유지합니다. 일반 텍스트 재배치는 지원하며, 표·그림·각주 등이 섞인 문서 전체의 재배치는 아직 제한됩니다.
- 글상자 높이 보정은 현재 단 안에서 뒤 문단을 이동합니다. 보정으로 페이지를 넘는 경우의
  일반 재페이지 나누기까지 검증한 것은 아닙니다.
- 미주는 독립 흐름으로 배치하므로 한컴의 미주 페이지 배치와 다를 수 있습니다.
- 수식은 분수·첨자 외에 루트, 행렬, cases/pile과 일부 기호를 추가했습니다.
  전체 수식 문법과 복잡한 장식·정밀 타이포그래피는 아직 지원하지 않습니다.
- 그림 자르기/회전/그룹 변환, 복잡한 도형, 다른 페이지 방향/여러 단 규칙 등은 추가 검증이 필요합니다.
- 배포용 HWP는 공식 문서의 키 유도/AES 경로로 읽습니다. 암호 입력이 필요한 HWP는 미지원입니다.
- 머리말/꼬리말, 글자 겹침, 덧말, 각주/미주, 캡션, 표 페이지 분할, 다각형/호/그룹,
  정적 OLE 그림과 레거시 차트를 추가했습니다. 곡선·그룹 변환·차트의 일부 표현은 근사입니다.
- 문단 번호를 추가했지만 확장 번호 형식과 일부 전용 글머리표 기호는 남아 있습니다.
- 한컴 PUA `(인)` 표시는 일반 문자열로 대체하고 비표시 TAC 문자는 숨깁니다.
  원본 전용 기호의 모양 및 모든 PUA 문자에 대한 완전한 대응은 보장하지 않습니다.

## 조사 근거

한컴이 공개한 HWP 5.0 명세와 제공된 HWPX XML을 사용했습니다.
설치된 뷰어의 실행 파일은 `mscoree.dll`을 참조하는 32비트 PE였고,
주요 DLL에서 문서 저장소·압축 레코드·글꼴·GDI 관련 연결을 정적으로 확인했습니다.
이것은 전체 렌더링 알고리즘 디컴파일이나 DLL ABI의 재사용 가능성을 입증한 것은 아닙니다.
본 Rust 경로는 그 DLL들에 의존하지 않습니다.

REA 6.4.0으로 `HwpEngineWrapper.dll`의 혼합 C++/CLI 구조를 확인했습니다.
메서드 검사는 REA의 메타데이터 용량 제한에 걸렸고, 네이티브 분석기는 미구성입니다.
내부 직렬화 함수 해석 완료를 주장하지 않습니다. 근거: `reference/viewer-analysis/README.md`.

전체 구현/미지원 상태는 [FORMAT_COVERAGE.md](FORMAT_COVERAGE.md)에 기록합니다.
공개 HWP 20개(기능 14개, 웹 문서 6개)는 모두 변환되며 현재 네 가지 QA 항목에서
충돌이 검출되지 않습니다. 렌더링 경고와 원본 충실도 제한은 별도로 유지합니다.
차트 파서는 MIT 공개 Rust 코드 일부를 사용합니다. `vendor/legacy-chart/LICENSE`와
`UPSTREAM.md`에 저작권, 원본 Git blob, 수정 내용을 보존했습니다.

공식 형식 자료: https://www.store.hancom.com/support/downloadCenter/hwpOwpml
