# Merged header bands — 2026-10-16

Repeating headers now use a complete, explicitly designated leading band of
cells. A merged header can span multiple rows, provided every covered cell is
marked as a header and the band ends before the body. An unmarked vertical merge
does not promote body cells into a header. Older models without cell flags retain
the previous single-row fallback.

Single-row tables and tables whose header would occupy the entire table do not
require a captured header in reflow. This removes the table-header rejection in
the supplied math document's full-reflow path. Its reflow output still differs
from the nine-page Hancom reference and is diagnostic only; default conversion
continues to use the saved layout. Native saved-table fallback behavior is retained
where needed to avoid changing cached page flow.

The shared band calculation is isolated in layout/table_headers.rs and used by
vector, row and oversized-row pagination. Tests cover a two-row merged header,
single-row flags in columns, unmarked merged body cells and the supplied math
document's equations/pictures. The five-page controlled merged-header sample was
rendered and visually checked.

168 tests and Clippy pass. The 43 baseline documents / 205 pages are byte-identical
to stage 26, with unchanged text/counts and zero geometry findings. This is a
complex-table subtask, not completion of the entire remaining roadmap.
